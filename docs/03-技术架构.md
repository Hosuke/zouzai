# 03 · 技术架构

## 技术栈

- **纯前端、零构建**：一个 `index.html` + 一个 `main.js`（约 1900 行），改完刷新即生效
- **three.js r160**：本地化于 `lib/three.module.js`，通过 importmap（`"three": "./lib/three.module.js"`）引用，无 CDN 依赖
- **音频**：WebAudio API + 4 个 AI 生成的循环 mp3（BGM/环境音/瀑布/篝火，位于 `audio/`）
- **存档**：`localStorage`（键 `qx-save-v1`）

## 核心机制实现

### 球面星球

- 星球为 `IcosahedronGeometry(R, 22).toNonIndexed()`，逐面顶点着色 + `flatShading`，形成低多边形地表
- 玩家位置用单位向量 `state.dir` 表示；移动 = 绕 `cross(up, moveDir)` 轴施加轴角旋转（`applyAxisAngle`，角速度 = 线速度 / R）
- 地形高度 `heightAt(dir)`：确定性噪声叠加，景点位置用 smoothstep 局部压平（保证建筑落地）
- `placeOnSphere(obj, dir)`：把物体 +Y 轴对齐表面法线，所有建筑/NPC/植被统一用此定向
- 植被/岩石用 `InstancedMesh` 批量散布（树、岩石、花、草），一次 draw call 一类物体

### 角色与相机

- 角色：胶囊身体 + 头 + 斗笠 + 背包 + 肩关节/髋关节枢轴四肢（几何体平移使原点在关节），走路摆动
- 相机：阻尼跟随（`1-exp(-dt*4.5)` 插值），`camYaw/camPitch` 拖动环绕，`camera.up` 缓动对齐表面法线——绕到星球背面不翻车
- 手感：阻尼加速度（`damp(curSpeed, target, 9, dt)`），Space 跳跃（vy=4.4，重力 -11.5）

### 任务与交互

- `computeInteraction()` 每帧按优先级计算当前可交互对象：送信 > 接信 > 打卡，驱动 `#prompt` 气泡和移动端按钮
- 送信引导：头顶金色箭头（切平面投影指向目标方向）
- 世界活化：`applyLiveliness()` 按明信片数量提升光照强度、显示蝴蝶群（≥4）、开启烟花（≥8）
- 烟花/蝴蝶/篝火/瀑布动画统一注册进 `animated[]`，主循环逐帧回调

### 音频

- `initAudio()` 在"开始旅行"点击手势中调用（浏览器自动播放策略要求）
- 4 路循环音源各接 GainNode；`updateAudio()` 每帧按玩家与瀑布/篝火的距离做二次方衰减：`gain = clamp(1-d/range,0,1)²`
- 音频素材由 AI 音效生成产出（英文描述 → mp3），可替换为正式授权音乐

### Canvas 动态纹理

瀑布水帘条纹、彩虹弧、景点名牌（pill 形）、纪念碑文、五角星、信封 sprite 均为运行时 Canvas 绘制转 `CanvasTexture`，零图片资源。

## 调试与测试

- URL 参数：`?auto=1`（跳过开始页）、`?tp=N`（传送）、`?card=N`（开明信片）、`?plan=1`（开行程单）
- 无头验证（CI 可用）：

```bash
chromium --headless=new --no-sandbox --use-angle=swiftshader --enable-unsafe-swiftshader \
  --window-size=1280,800 --virtual-time-budget=12000 \
  --screenshot=shot.png --enable-logging=stderr "http://127.0.0.1:8791/?auto=1" 2>&1 | grep CONSOLE
```

## 已知限制

- 移动端为简配体验（摇杆 + 按钮），高密度植被场景在低端机可能掉帧，可按设备降 `InstancedMesh` 数量
- 音频必须经用户手势启动；iOS Safari 对 WebAudio 解码更严格，需真机回归
- 无后端：行程单数据为按真实里程估算的演示数据，正式版需接入实时路况与在线预订

## 演进方向（如未来需要）

- 若加入真实拼团/支付/账号：需补后端（本项目可平滑升级为前端 + API 两层，游戏层不动）
- 若景点继续增多：把 `LANDMARKS` 与建造器拆成 `content/` 数据文件 + 按需建造
